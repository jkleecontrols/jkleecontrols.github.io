Symphony Local

A kanban board that watches my AI coding sessions instead of asking me to update it.
Source and setup on GitHub

Why I built it

I usually have Claude Code or Codex running in several folders at once — a paper, a simulation, this website. Nothing told me which one was blocked on a question, which had finished, or whether what it did still passed the project's own checks, so I kept walking through terminals one at a time.

A normal kanban board did not help: it is a second thing to keep in sync, and it drifts within a day. So this one reads the machine instead. I never move the cards.

What it does

  • Each card is a project folder, and the agent for that card runs with the folder as its working directory.
  • The column follows the session: In Progress while a turn runs, Human Review when it stopped to ask something, Ready when it is open and idle, Done when the process is gone.
  • A desktop notification when a session needs an answer, so the board does not have to stay open.
  • Finished runs record what changed in git and whether the project's own check command still passes — the pass and fail panels in the screenshot above.
  • Agents are shell commands in a config file, so different cards can run different CLIs. Claude Code and Codex CLI are wired up; aider and goose are detected.
  • An independent implementation of the OpenAI Symphony service specification.

Trying it

Node 20 or newer, and nothing else — no npm dependencies, and tasks live in a local JSON file. Clone the repository, copy the example task file, run npm start, and open 127.0.0.1:8787. Whichever AI CLI you want to dispatch has to be installed and signed in already.

It is early, and built around my own setup. Notifications and session detection use macOS tools, the server binds to localhost with no authentication, and auto-dispatch does not sandbox an agent — the git guard makes its changes visible and reversible, but it is not a fence. The board also renders snippets of session transcripts, so it shows conversation text on screen. It works and it is documented, but nobody else has run it yet. If you try it, I would genuinely like to hear what breaks.
